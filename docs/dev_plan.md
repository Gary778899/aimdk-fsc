# 项目开发总计划

更新日期：2026-10-30。适用 X2 Ultra、SDK 1.1、URDF v1.3.0。

## 文档范围与目标

本文是项目唯一总计划，记录开发阶段、当前状态、主要交付物、依赖、完成条件和影响整体路线的待确认事项。阶段状态依据用户回传结果及专题记录更新，分别标明已实现、已验证和未覆盖范围。

具体命令、参数、接口契约、算法设计和实验结果在对应包 README、专题设计或实验记录中维护；本文概述其对阶段进展的影响并插入链接。通用开发规则与部署流程引用 [AGENTS.md](../AGENTS.md) 和[根目录说明](../README.md)。调试经过、逐次日志、完整数据和历史方案不在本文展开。

## 开发阶段

阶段表示主线顺序，允许提前准备和并行研究。阶段四的数据与 ACT 路线依赖阶段二、三；力估测的模型收集、语义核实和离线分析可提前进行。阶段五各任务分别确定依赖和验收，不要求使用相同算法。

| 阶段 | 状态 | 主要交付 |
| --- | --- | --- |
| 一：项目框架搭建 | 基础已建立，持续维护 | 工作流程、分层工作空间、包边界与文档入口 |
| 二：数据采集功能 | 部分实现，待当前版本复验 | 独立采集、会话控制、保存与读回 |
| 三：上半身遥操 | 进行中 | 双臂 PICO 连续遥操、轨迹录制与播放验证 |
| 四：示教数据、ACT 与力估测 | 待开展；已有模型与补偿探索 | 插孔示教数据集、ACT 训练与执行验证；并行力估测研究 |
| 五：面向任务的开发验证 | 待开展 | 递奖状、抓水瓶、ACT 与三维力估测结合的简单插孔任务 |

### 阶段一：项目框架搭建

**目标：** 建立本地编写、用户同步、机器人容器构建与验证的工作流程，明确厂商 underlay、自研 overlay、包职责及文档组织。

**当前状态：** 工作空间与自研包已整理，`aimdk_test`、`aimdk_functions` 于 2026-10-22 经用户确认完成容器构建。后续新增入口和包迁移分别验收。

**完成条件：** 工作流程、同步和构建入口可用，源码与安装来源明确，各包有操作说明，开发总计划与专题文档职责清晰。基础建立后持续维护。

**关联文档：** [根目录说明](../README.md)、[实验包](../overlay/src/test/README.md)、[功能包](../overlay/src/functions/README.md)。

### 阶段二：数据采集功能开发

**目标：** 为后续研究与开发提供独立采集、会话控制、质量统计和读回能力。当前实现双臂与夹爪反馈的统一 JSONL 帧及可选原始 MCAP；其余消息类型随后续阶段的任务需求逐步扩展。

**当前状态：** 部分实现。2026-10-26 已完成一次录制和本地读回，共 12,869 帧，平均输出 50.002 Hz，正常收尾、无统一帧写盘丢弃；夹爪映射错误导致字段缺失。映射修正、停止日志、会话命名及包名迁移待容器复验，源时间为零等问题继续保留质量标记。

**主要工作：** 复验当前版本，核对夹爪字段、时间质量、计数与收尾；独立验证原始 MCAP 读回。原始采集器设计作为后续扩展依据，消息类型按遥操、训练及其他研究任务的需求分批接入，并补充阶段、图像及版本／负载等元数据，明确源时间、接收时间和数据配对方式。

**完成条件：** 当前包完成启动、开始、状态查询、停止和读回；有效样本、缺失字段、异常退出与时间问题可识别，原始消息内容可核对，数据持久化和同步保护明确。后续新增消息类型随对应阶段任务验收；轨迹执行播放在阶段三验证。

**关联文档：** [采集说明](../overlay/src/data_collection/README.md)、[采集设计](dev_data_collection_design.md)。

### 阶段三：上半身遥操功能开发

**目标：** 保留下半身原厂运控，通过原生上肢接口实现双臂 PICO 连续遥操，并验证遥操轨迹的录制与机器人播放。

**当前状态：** 已完成实际反馈 FK→IK→FK、小幅端点和直线运动，以及显式位置偏置补偿的初步实验。当前结果限于已记录姿态和动作；实体精度、TCP、双臂同步及 PICO 连续遥操继续验证。夹爪基础开闭已有旧流程结果，物体夹持仍需独立验证。

**主要工作：** 完成单臂适配、双臂统一提交、PICO 相对位姿映射与接管语义，建立连续记录及轨迹播放入口。记录目标、实际发送值、反馈、夹爪、模式和时间关系；补偿保持显式实验选项，收益通过同起点、明确负载的重复对照评价。

**完成条件：** 双臂 PICO 连续遥操可用于示教采集，接管、保持、结束及异常行为有记录；录制一段包含双臂与夹爪动作的轨迹，保存后读回，并在机器人执行播放。核对记录时间顺序、播放目标、实际反馈和夹爪动作，确认整段执行完成，记录偏差及失败原因。播放数据表示、速度和执行条件在专题设计中确定。

**关联文档：** [遥操规划](dev_teleop.md)、[第一阶段适配与验证](dev_teleop_part1.md)、[功能包说明](../overlay/src/functions/README.md)、[已有验证记录](archive/x2_upper_body_validation_20261029.md)。

### 阶段四：上半身示教数据、ACT 与末端三维力估测

本阶段分两条并行路线，分别记录进展与验收。

**路线一：示教数据与 ACT。** 优先以简单 peg-in-hole 为首个训练任务。利用阶段三的遥操与录制能力采集示教，明确观测、动作、时间对齐、任务阶段和成功标记，形成可追溯的数据集及训练／验证划分；完成 ACT 训练、模型推理与原生执行接口适配。

完成条件：数据集可读、训练配置与模型可复现，训练后的策略完成机器人执行验证，记录任务结果、失败阶段及适用工况。示教数量、输入模态、动作表示和首轮成功判据在实验方案中确定。

**路线二：末端三维力估测。** 核实 effort 的物理含义、单位、符号和传动侧，结合模型、负载、重力／摩擦基线及雅可比开展估测，明确坐标系、接触点和有效工况。已有位置偏置补偿作为相关探索，其效果与力估测准确度分别评价。

完成条件：形成可复现的算法与实验记录，说明模型假设、估测结果及局限；定量精度评价采用的独立参考（ground truth）方案待研究确定。力估测参与插孔或其他任务的方式作为研究内容，通过实验选择。

**关联文档：** [模型对比](archive/x2_urdf_v1_3_comparison.md)、[已有补偿实验](archive/x2_upper_body_validation_20261029.md)。数据集、ACT 和力估测专题文档在对应工作启动时建立。

### 阶段五：面向任务的开发验证

**目标：** 将遥操、轨迹、视觉、策略和力估测能力用于具体任务，在声明工况下评价成功率、误差和失败原因。

| 任务 | 主要内容 | 完成条件 |
| --- | --- | --- |
| 语言指令控制双臂递奖状 | 双臂夹持、持平、递出、等待指令、释放与撤回；明确材质、装载方式和指令语义 | 在约定次数内完成全流程，记录姿态、滑移／掉落、释放时机及指令误触发 |
| 单臂抓取桌面水瓶 | 先固定位置完成接近、抓取、提起、保持与放下，再扩展视觉定位；明确瓶型、负载与抓点 | 在声明位置范围和重复次数下完成任务，区分定位、夹持及掉落失败，记录定位误差和成功率 |
| 简单 peg-in-hole | 基于阶段四 ACT 基线，研究三维力估测的接入方式并验证效果；明确孔轴几何、配合间隙和初始偏差 | 完成插孔执行及重复实验，记录成功率、时长、失败阶段，比较 ACT 基线与引入力估测后的结果 |

各任务在实验前确定工况、重复次数和判据。实体定位使用独立测量，反馈 FK 单独报告；力估测的参考方案及任务使用方式以研究结果为依据。递奖状和抓瓶可先利用现有轨迹与状态机推进。
