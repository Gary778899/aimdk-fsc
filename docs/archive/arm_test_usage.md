# X2 Ultra 单臂第 7 轴测试

`arm_test` 默认只读。显式 `--execute` 执行左臂第 7 轴 `left_wrist_roll_joint`（完整双臂数组索引 6）的一次往返，默认 +2°、每段 3 s。其他 13 关节固定为 URS 切换后实测起点，两侧夹爪使用模式 1 持续重发切换后实测开度。脚本不控制腰腿、不发布行走指令，原生运控继续管理站立。

## 同步、构建与测试

本地仅修改及静态检查。使用 `.vscode/tasks.json` 的“机器人：预览同步”和“机器人：推送工作区”同步代码；现有任务排除 Markdown 和 log。用户进入机器人开发板开发容器，在实际项目根目录加载 Humble/SDK 环境后执行：

```bash
colcon build --packages-select py_examples
source install/setup.bash
python3 -m pytest -q src/py_examples/test/test_arm_test.py src/py_examples/test/test_arm_test_adapter.py src/py_examples/test/test_arm_test_motion.py src/py_examples/test/test_head_test.py src/py_examples/test/test_head_test_adapter.py
ros2 run py_examples arm_test --help
ros2 run py_examples arm_test
```

测试使用模拟服务和反馈，不初始化 DDS 或连接机器人。`test_arm_test_motion.py` 覆盖执行适配器正常往返、完整目标和夹爪编码，以及卡住、其他关节漂移、夹爪变化、迟到查询、失效反馈、外部接管、拒绝模式切换等分支。缺少消息依赖导致的 skipped 不计为通过。

用户已提供先前版本的容器构建成功记录；本次 3°阈值及异常交接修订尚未在容器构建或运行 pytest。本机本地不会运行项目或测试，新增模块面向 Python 3.10 / ROS 2 Humble。

## 用户显式启动运动

先确认容器测试通过、机器人已处于站稳的 STAND_DEFAULT、双夹爪空载、左腕 roll 正向 2°范围及线缆空间合适，再由用户启动：

```bash
ros2 run py_examples arm_test --execute
```

一次往返完成后退出，不自动循环或重试。可用 `--amplitude-deg -2` 更改方向，幅度绝对值仅允许 0.5..2°；`--leg-seconds` 仅允许 3..10 s，峰值速度不超过 2°/s。不自动换侧或换关节；右臂第 7 轴为索引 13，始终保持起点目标。

`--execute` 表示用户选择执行这一小幅测试，并已现场确认空载与空间；这些条件无法由状态反馈自动证明。URS 首帧前和退出后夹爪/身体的行为仍需本次现场观察，不能根据头部验收假定 URS 接管平滑。不要为测试主动断网。

## 姿态约束与夹爪编码

本机只读基线已审阅，见 [基线记录](arm_test_baseline_review_20261020.md)。随附 URDF 的右肩 roll 上限与实测相差约 0.246°，尚未核定模型与本机的对应关系。实现采用这次已审阅的完整 14 关节姿态作为**起始姿态检查参考**：切换前每项起点必须在参考值 ±3°内；切换后非测试关节允许相对切换前偏移最多 3°，重新采集实测目标。左腕 roll 整条路径限制在 ±5°的小窗口。参考数组绝不作为下发目标，不能用它复位机器人。

这是针对本机当前站姿的经验检查范围，不是厂家机械限位核定，也不修改 URDF。其他 13 项仅重发切换后的实测位置，不裁剪右肩 roll，不向模型边界纠正位置。换姿态、换机型或超过参考窗口应停止并重新审阅，不绕过检查。

`upper_body_control.py` 的夹爪示例使用 `HAND_CLAW_OPEN_CLOSE=1`、`hand_pos=[0.5,0.5]`，含义是左右半开位置目标。执行版沿用模式 1，但替换为 `[左实测开度,右实测开度]`；两侧都必须有有效反馈。HEAD_ONLY 中的模式 0/空数组不用于 URS。位置重发不能保证夹持力，也不是专用 hold 指令。

本次基线两侧开度为 0，因此若实时反馈仍如此，会发送 `[0.0,0.0]`：这里的零是实测闭合位置目标，绝非忽略指令。实际值始终重新采集，不固定使用历史零值。

## 执行流程与中止

1. 仍先完成默认只读基线：GetMcAction 前后确认 STAND_DEFAULT / RUNNING，body=STAND。执行前要求观察期手臂位置范围不超过 0.2°、夹爪范围不超过 0.005，夹爪持续 state=0、速度绝对值不超过 0.01。
2. 再检查当前姿态、夹爪，并观察约 0.3 s 静止状态。仅发送一次进入 URS 请求，验证 Set 响应和实际模式，不重复设置初始站立。
3. 查询确认 URS 后，在 0.3 s 内取得晚于确认点、源戳前进的 arm/hand/MC 反馈，建立完整 `q0` 及两侧开度。拒绝接管期间腕 roll 超过 0.5°、其他关节超过 3°或夹爪超过 0.01 的变化。首帧前检查左腕相对 q0 的偏差不超过 0.2°、其他关节不超过 3°。
4. 首帧完整目标等于 q0，夹爪等于实测开度。等待更新的双臂和夹爪反馈，确认首帧后无明显偏移，再以约 50 Hz 发布五次多项式轨迹；源戳采用 SDK 的全零接收时刻方案，不伪造反馈戳。
5. 持续要求新鲜反馈、body=STAND、URS / RUNNING；异步 Get 查询每约 0.1 s 一次，回复超过 0.3 s 或模式确认超过 0.4 s 即失败。最大命令发布间隔为 80 ms。测试关节跟踪误差不超过 1°，其余关节不超过 3°；夹爪须保持静止，开度变化不超过 0.01。URS 期间其他 13 关节相对切换前姿态的偏移也限制在 3°。
6. 出程及返程分别验证端点：第 7 轴误差不超过 0.2°，其他关节不超过 0.3°，连续保持 0.3 s；每段最多额外等待 2 s。
7. 正常返程后，请求并确认 STAND_DEFAULT。有新鲜反馈和 URS 归属证据期间继续发送完整返程终点目标；一旦观测到切换中或离开 URS，停止发布。记录交接时间及最后发布间隙。随后观察约 0.3 s，核对夹爪开度，再查询确认站立，才报告 PASS。这不能保证交接零间隙或原生站立接管后手臂不再调整。

Ctrl+C、反馈/跟踪/时序异常会停止发布并中止轨迹，不盲目返程。若本工具已发出 URS 请求且没有检测到外部接管，则先进入独立的异常交接检查流程，在新鲜反馈和新查询确认本工具仍处于 URS 时，最多尝试一次返回站立；已触发的关节偏移、跟踪误差或夹爪运动不会再次阻断交接查询，但反馈失效、硬件故障、body 非站立及外部接管仍会阻止自动切换。异常交接全程不恢复目标发布；已在站立则只记录，外部接管不抢回模式。反馈失效、服务不可用或故障锁存时，自动交接可能无法完成，终端会报告未确认；不能将停发视为固件保持或急停。

## 反馈与诊断

使用 BEST_EFFORT + TRANSIENT_LOCAL 订阅 `/aima/hal/joint/arm/state`、`/aima/hal/joint/hand/state` 和 `/aima/mc/common/state`。手臂要求恰好 14 个唯一预期关节，错误码/总体状态为 0，位置、速度、力矩有限。手部要求两侧 CLAW=2、各一项、开度 0..1、faultcode=0。默认只读允许留存运动/堵转状态用于诊断；执行阶段必须静止。

所有流要求源世界戳非零且实际前进，接收年龄和源时间冻结不超过 200 ms，源戳相对本机时钟年龄为 -50..200 ms，ROS 时钟不得回退或冻结。MC 同样采用 200 ms 门槛。TRANSIENT_LOCAL 首帧不满足源时间前进条件，故障锁存，FSM 仅记录不作编码判断。

默认日志路径为项目根目录 `log/arm_test_*.jsonl`，可用 `--log-dir` 指定。`--timeout` 及 `--observe-seconds` 均支持 1..10 s，默认分别为 5 s 和 2 s。日志退出时写盘，反馈原文约 10 Hz 留存；执行中逐帧记录完整指令、实际姿态、源/接收年龄，并记录模式切换、起点、端点、退出及中止结果。请提供完整终端输出和 JSONL，并说明身体、非测试手臂及夹爪在接管/退出时是否有可见变化。

## 2026-10-20 执行失败后的修订

根据现场确认的模式切换抖动，将非测试关节相对切换前及目标位置的偏移保护设为 3°。左腕接管跳变 0.5°、跟踪误差 1°、端点腕部 0.2°/其他关节 0.3°的到位标准不变；若抖动始终未收敛，仍可能以端点未到位结束，并尝试交接站立。切换前静止检查保持原设置；历史参考姿态窗口后续按用户要求扩大为 ±3°。

异常交接修复了恢复查询复用运动漂移检查而无法发出返回站立请求的问题。新增模拟回归覆盖持续超限偏移后交接、反馈失效不交接，以及 0.6°/2.9°/3.1°接管偏移边界。本地仅完成静态检查，容器内测试由用户同步后执行上述 pytest 命令。
