## 已确认事实

### 首帧后下沉

零增量实验中，motion_begin之前已记录的关节位置与各自采样起点一致。
首次观察到超过0.1°的关节变化在首帧记录后约41～44ms，随后约0.2～0.3秒内形成明显偏差。
该时间基于反馈接收时刻，不等同于硬件响应延迟。

| 约动作开始后0.3秒 | 补偿开 | 补偿关 |
| --- | ---: | ---: |
| 左/右肘增量 | +2.384° / +2.538° | +2.296° / +2.384° |
| 左/右肩roll增量 | −1.857° / +1.868° | −1.736° / +1.813° |
| 左/右腕Z变化 | −7.80 / −8.05mm | −7.04 / −7.39mm |

同时存在向内、向后偏移。关闭补偿后偏差基本持续至结束；开启补偿后有所回收。
X+20mm实验中同样观察到启动瞬态，因此该现象不依赖非零TCP请求。

### 首帧数值与反馈一致

关闭补偿的零增量测试，全部265帧14关节目标均与采样值相同；首帧与发布前最近反馈的最大差为0°。
开启补偿时理想目标仍全程不变，首帧与最近反馈的最大差仅0.000001665°；
两组最近反馈的记录时刻分别早于首帧8.47ms、5.51ms。
按关节名称和SDK槽位检查，未发现单位转换、左右顺序或关节重排导致的大目标差。
源码直接将rad目标写入arm_pos；尚未录制订阅端实际接受的底层目标。

### 补偿有效性与启动覆盖不同

X+20mm配对的起点最大关节差约0.264°，代码和模型版本一致。
开启补偿后，左/右终点位置误差分别下降约67%/62%，但X实际行程仍只有约16.04/13.62mm。
肩roll、肘的理想目标误差明显改善，肩pitch和右腕yaw改善较小。

补偿按整段5秒轨迹的五次进度引入。约0.3秒时只有最终偏置的0.16～0.17%，
因此当前开启补偿不能避免前0.3秒的下沉。
零增量的开启与关闭两组起点最大关节差约0.912°，不作为严格同起点的定量收益配对。

### 模式与来源未记录到切换

3479378a、a9046813和两次零增量日志的全部mc反馈中：
action_desc保持UPPERBODY_REMOTE_SPLIT、status=100，input_source保持空名称、priority=0、timeout=0。

- 上肢脚本与采集器默认读取相同的SDK双臂、夹爪反馈话题。

## 根因假设与待核实项

### 重复执行对原假设的约束

2026-10-30现场补充：从SD切换到URS后，每次执行upper_body_control均观察到下坠，
并非只出现在切换后的第一次执行。此项为用户现场观察，尚未用连续记录串联各次执行及间隔。

这使“SD留下的带载保持仅在首次外部命令接入时被替换”不足以单独解释现象。
若以保持路径切换解释重复下沉，还需证明停止发布后会重新进入某种保持状态，
并在下一次接入时再次改变内部参考、积分项或前馈。现有公开模式记录不能确认这种内部切换。

### 每次重采样也可能重新产生负载偏差

当前源码每次运行都从反馈构造CapturedTarget，并从该位置开始规划；完成后停止发布并销毁发布器。
因此相邻两次执行的目标未保持连续：上一次最后发送的目标与下一次采样的实际位置可能不同。
依据见[启动与采样](../../overlay/src/functions/aimdk_functions/upper_body_control.py)及
[执行与停止](../../overlay/src/functions/aimdk_functions/upper_body_execution.py)。

用单关节静态模型说明一种待验证机制：

```text
Kp × (q_cmd − q_actual) + τ_ff = τ_load
```

其中Kp为等效位置刚度，τ_ff为前馈支撑，τ_load为该姿态下的重力等负载力矩。
该式用于解释可能机制，不代表已知厂商控制律或参数。
若前馈未完全平衡负载，稳态位置误差也会提供支撑力矩。
下一次将q_cmd改为当前q_actual，会把位置误差项归零；即使前馈、刚度和控制路径完全未变，
关节仍可能再次沿负载方向偏移，直到建立新的平衡。
例如上一目标为0°、实际稳定在2°，下一次以2°作为目标，仍可能继续偏移；具体幅度取决于姿态和负载。

因此，“每次执行都下沉”可以与反复重置位置参考相容，无需假定每次都关闭重力补偿。
已有日志确认了单次首帧接近实际反馈，尚未比较相邻执行的“上一末帧命令—下一首帧命令”，
也未记录底层实际采用的参考与力矩，当前不能将此机制确认为根因。

其他待区分项为反馈与命令的校准/零点语义、其他发布者及实际命令仲裁。
当前已排除本次脚本首帧大位置差、非零TCP路径及补偿突然全量加入作为必要触发条件。

### 区分验证与厂商核实

后续验证优先关闭自研位置偏置补偿，连续记录执行前、执行中、停发间隔及下一次启动的反馈与实际发布目标：

| 对比操作 | 观察及用途 |
| --- | --- |
| 同一发布会话内持续发送完全相同的完整目标 | 观察首次下沉后是否稳定，建立不重采样、不停发的基线 |
| 持续发布中将目标改为当时实际位置 | 若再次沿负载方向偏移，支持重置位置误差即可触发下沉；该操作仍不能确认厂商具体控制律 |
| 停发后重发上一末帧完整目标，与停发后重采样目标对比 | 同时记录停发阶段的位置变化；固定目标重发也有瞬态，则继续调查中断恢复与接入行为 |

以上为待执行的验证设计；新增[分段实验命令](../../overlay/src/test/README.md#持续发布的两段平移实验)
提供持续发布、沿用上一目标和重新采样的对比入口，尚未完成机器人构建及真机验证；
停发后重发旧目标的分支尚未实现。
它们用于区分机制；真实内部参考、积分项与前馈仍需厂商提供证据。

优先向厂商核实：

1. URS无外部命令时如何保持双臂，首次及中断后重新收到命令时如何接入。
2. arm_pos与实际角度及内部位置参考的关系；URS持续接收命令时是否保留重力前馈，带载静止是否允许位置稳态误差，是否要求外部偏置。
3. 接入前后是否重置内部目标、积分项或改变刚度/前馈，能否只读获取这些内部量。

下一次执行验证需覆盖持续会话中的保持、Grip重新接管及停止发布后的表现。
根因未明时，不直接通过全量首帧补偿、改source或扩大容差掩盖启动变化。

## 已有验证能支持什么

包内模型/限位适配、实际反馈FK/IK、18条小范围离线连续轨迹、完整原生消息发送、
双臂同帧单次平移、部分关节与夹爪动作已有可复核日志。
18条离线回放共4518帧均accepted，单侧计算中位值约2.8ms；
左侧最大16.32ms、右侧最大3.86ms，含候选检查及FK，使用腕原点TCP。
这些回放分侧进行，不能据此宣布双侧在线IK加反馈、补偿、发布及写盘在20ms内全部完成。

尚无完整双臂逐帧在线目标执行、omnipicker TCP下的连续回放、PICO输入/重定位/失联验证，
纯旋转与完整位姿实机覆盖、退出保持及实体精度验收也未完成。
人工验收报告部分填写accepted，但覆盖和观察记录不足以宣布第一阶段全部完成。
