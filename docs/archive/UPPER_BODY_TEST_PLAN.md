# X2 Ultra 上半身独立控制测试计划

## 已确认需求

- 机器人：X2 Ultra，末端夹爪；固件 1.1.5，用户确认与当前 SDK 1.1.0 配套。工作空间 `version` 为 `aimdk v1.1.0-gfaf4c94`。
- 环境：真机、网线连接、ROS 2 通信已由用户验证。本机开发环境的可运行性与机器人固件上的行为分别验收。
- 目标：控制双臂，下半身和腰部交由原生运控保持站立及平衡；允许必要的平衡调整，不主动行走，不下发腿腰关节目标。
- 顺序：先头部单关节小幅低速往返，通过联合验收后再进行单臂单关节测试。夹爪暂不主动开合。
- 正常流程：检查反馈与模式 → 确认 `STAND_DEFAULT` → 切换并确认对应控制模式 → 从当前实际姿态平滑运动 → 返回测试起始姿态 → 切回并确认 `STAND_DEFAULT`。
- 测试起始姿态来自实际反馈，不以全零目标或未核实的默认姿态代替。系统默认站立姿态由原生运控决定。
- 用户与主代理分步验收。开发授权不等于启动真机运动；每阶段真机运动由用户明确启动。按 AGENTS.md 在本地修改、使用现有 rsync 配置同步、在机器人开发板容器内构建和测试。

## 接口依据与待核实事项

- 参考：`src/py_examples/py_examples/upper_body_control.py`、`set_mc_action.py`、`get_mc_action.py`、`src/aimdk_msgs/interface` 及随 SDK 附带的本地 1.1.0 文档。
- 在线参考：<https://x2-aimdk.agibot.com/zh-cn/latest/Interface/control_mod/upper_body_control.html>。前期两次访问超时，不将本地文档解释为已在线核验的固件 1.1.5 行为。
- 上肢指令：`/mc/upper_body_command`，`UpperBodyCommandArray`；推荐 50 Hz、BEST_EFFORT + VOLATILE。头部 2 关节，双臂固定 14 关节（左 7 + 右 7），单位 rad。
- 头部使用 `HEAD_ONLY`；双臂/夹爪使用 `UPPERBODY_REMOTE_SPLIT`。上肢专门章节说明 URS 下头部目标无效，与模式总表/示例部分注释不一致；优先遵循专门章节，真机分阶段核验。
- 关节控制专章明确：原旗舰 X2 Ultra 仅头部 yaw 有效，旗舰焕新版才有 yaw/pitch；固定两槽消息不能推导出两个可动自由度。因此首版仅开放 yaw 测试，并在只读阶段核对实际反馈名称和有效槽。
- 运控 FSM 存在重要资料冲突：本地 HTML 写 STABLE=4，但实际 SDK `McFsmState.msg` 中 STABLE=2、SAFE=4。按用户要求，head_test 不再使用 FSM 作为门槛；改用 GetMcAction 的 STAND_DEFAULT / RUNNING 作为启动模式条件，保留 body=STAND 和反馈检查。此变更不代表已核定 raw=4 的含义。
- 文档说明非零命令时间戳与接收时间差不得超过 200 ms；跨机时钟及零时间戳方案须明确选择与说明，禁止伪造反馈新鲜度。
- 头部已实测：反馈话题、yaw/pitch 名称和状态/时效检查、HEAD_ONLY 正常切入与返回站立。后续待查证：双臂/夹爪反馈基线；URS 模式接管与退出；输入源机制是否适用上肢；异常断流后的运控行为；夹爪保持当前状态的编码与接管表现。
- 对资料未说明的行为标注“待真机/厂家确认”，不假设停发即保持，不用阻尼/零力矩作为站立测试通用退出方式。
