评审日期：2026-10-22。依据当前工作区源码进行本地静态审阅；本轮交付为整理意见和实施顺序，未移动包、重构控制代码、修改同步配置或执行容器验证。

用户已确认 `robotop` 为未修改的官方 SDK 包，采集包应能独立运行。`locomotion_wrapper` 已加入当前 `src/`，本轮已审阅其节点、校验核心、配置、launch、监视脚本和 8 个 gtest 用例。下面关于该包的判断依据当前源码；未执行容器构建或测试，不沿用历史验收结果。

## 1. 包归属与建议边界

当前 `src` 一级包目录的 manifest 共包含 9 个不同包名，未发现一级包重名；这不是 colcon 包发现或容器安装空间核查结果。

| 包／目录 | 归属 | 建议职责与依赖边界 |
| --- | --- | --- |
| `aimdk_msgs` | 官方 SDK | 保留厂商协议和生成逻辑；自研代码依赖它，不向其中加入实验业务接口 |
| `ruckig` | SDK 携带的第三方库 | 保留现有版本和接口；自研算法按需依赖，不混入实验业务 |
| `examples`、`py_examples` | 官方示例 | 保留示例；自研代码不把示例模块作为公共库 |
| `robotop` | 官方 SDK，用户确认未修改 | 保持官方诊断工具边界，不将自研采集或实验流程放入其中 |
| `aimdk_test`（`src/test`） | 自研 | 头部、手臂实验入口及各自控制策略；内部公共模块可复用，不兼任采集器或标准状态转换器 |
| `aimdk_functions`（`src/functions`） | 自研 | 独立功能命令，目前为音量／静音；避免发展为所有公共代码的汇总包 |
| `data_collection_edge_agent` | 用户新增的采集包 | 订阅、录制、START／STOP 和存储错误处理；不承担运控切换、夹爪控制或厂商关节映射 |
| `locomotion_wrapper` | 已加入的自研只读观测包 | 厂商关节状态聚合、标准 IMU 校验转发；不依赖采集器或测试入口。当前没有命令发布、模式切换或策略推理，无需先拆出控制子包 |
| `aimdk_bringup`（建议后续新增） | 自研实验组合层 | 选择观测 profile、配置录制话题和数据路径、组合节点；依赖观测包和采集包，不提供控制算法 |
| `tools/`（按需恢复） | 离线与主机工具 | ZMQ 控制客户端、MCAP 导出和分析；不由采集 C++ 节点调用，不与控制循环耦合 |

建议保留当前平铺结构，先不引入 `vendor/`、`research/`、`applications/` 多层移动。现有包已基本分离，目录搬迁的收益小于入口、日志定位和同步迁移成本。外层目录与 ROS 包名不同合法；以后如将 `src/test` 改名为 `src/aimdk_test`，需同时修复源码路径探测，不只修改目录名。

## 2. locomotion_wrapper 加入后的判断

建议保留现有包名和独立包边界，无需再从该版本拆出控制或推理模块。已检查的节点只订阅厂商 `JointStateArray` 和标准 `Imu`，发布标准 `JointState`、`Imu`；`joint_watch` 只订阅并输出日志。未发现执行器命令发布器、运动服务客户端、策略模型或对采集／测试包的反向依赖。

实际依赖中，观测包与采集 C++ 节点已是不同层；耦合主要来自采集包的 manifest 和联合 launch。目标关系仍为：

```text
aimdk_test ───────────────→ aimdk_msgs
aimdk_functions ──────────→ aimdk_msgs
locomotion_wrapper ───────→ aimdk_msgs + sensor_msgs
data_collection_edge_agent → sensor_msgs + rosbag2 + ZeroMQ
aimdk_bringup ────────────→ locomotion_wrapper + data_collection_edge_agent
```

观测包已存在，组合包尚未创建。联合 launch 的源码依赖缺失已解除，但这不等于已在容器安装成功或已能录到有效数据；仍建议将组合入口放入 `aimdk_bringup`，避免采集包长期强依赖特定上游生产者。Python 公共逻辑不作为两个 C++ 节点的运行依赖。

### 当前实现已具备的基础

- [state_validation.hpp](../src/locomotion_wrapper/include/locomotion_wrapper/state_validation.hpp) 将校验与节点适配分开，直接处理消息结构，不创建 ROS 节点；可继续保持包内纯逻辑核心，无需为此新增公共 C++ 包。
- 校验源时间相对 ROS 时间的年龄、monotonic 接收年龄、组间源时间差、关节集合、域／关节错误和有限数值；IMU 还检查分量可用性、协方差有限性及四元数模长。
- 聚合使用各组最早的源时间戳，IMU 保留原消息；关节发布依据接收代次变化，IMU 依据 pending 标志，2 ms 定时器不会仅因定时触发而不断刷新同一缓存的时间。
- [state_validation_test.cpp](../src/locomotion_wrapper/test/state_validation_test.cpp) 中有 8 个 gtest 用例，覆盖映射、缺组、年龄、组间偏差、部分腿关节、错误值和 IMU 等静态校验。此处仅确认测试源码存在，未运行。

### 新确认的限制与建议

| 优先级 | 源码事实 | 整理意见 |
| --- | --- | --- |
| 高 | [默认 YAML](../src/locomotion_wrapper/config/wbc_observer.yaml) 只要求腿部，头／臂／腰订阅被指向 unused 话题，IMU 为胸部；直接 `ros2 run` 则使用节点默认的全部真实关节输入 | 保留旧 WBC profile，另建上肢 profile；文档区分直接启动与配置启动。仅把 `require_arm` 设为 true 不够，还需真实输入话题和经过核实的完整 `arm_expected_names`。未使用组应显式禁用订阅或配置隔离，避免其到达后变陈旧而压制聚合 |
| 高 | `compose_joints()` 以 set 比较 `expected_names`，却按输入消息中的原始顺序填充输出 | 配置列表只约束集合，不固定输出顺序。消费者按 `name` 建立映射；如未来需要稳定顺序，显式实现按配置重排并添加输入重排用例。不能将当前输出数组直接当作控制命令的固定关节顺序 |
| 高 | `time_error()` 只比较当前源／接收年龄，不保存上一帧源时间、源时间推进时刻或 ROS 时钟推进历史 | 不能替代测试包的 `FeedbackMonitor`。若 ROS 时间暂停而同一源时间的消息持续到达，当前两种年龄检查可能持续通过；在年龄窗口内的源时间回退也没有独立拒绝逻辑。为实验记录增加推进／回退的状态监视与回放时间策略，或明确暂停时的行为，再考虑扩大复用 |
| 中 | 聚合校验失败和 IMU 校验失败分别通过节流日志报告，没有结构化有效性诊断话题 | 观测包后续发布按流的无效原因、最后有效时间／计数；采集端记录诊断。当前只能从标准话题停止和日志得知问题，不能把“有效性诊断”写成已实现的话题接口 |
| 中 | 头臂腰腿按各自最新缓存合并，使用最早源时间；任一新接收都会推进 joint generation | 相同源时间的重复到达仍可能再次发布；多个不同聚合可能具有同一最早源时间。记录层保留这些样本和原始组时间，不将其视作硬件同步或仅按聚合时间去重 |
| 中 | 可选组未到达时忽略，已到达但失效时抑制整个关节聚合；有效消息恢复后自动恢复 | 这是当前明确的观测语义，保留并文档化；它不同于测试脚本的永久错误锁存。新增用例覆盖可选组先有效后断流、恢复、跨组重复名字等路径 |

该版本没有 `HandStateArray`、`McCommonState` 或上肢目标订阅，因此不能补齐夹爪、模式和命令记录。不要为了录这些字段将实验状态机放进观测包；在采集层扩展原始话题支持，标准化转换按明确用途增加。

公共能力的判断随之收窄：两个 Python 实验入口共享的日志、监视和插值仍先在 `aimdk_test/common/` 整理；观测 C++ 核心留在本包。跨语言统一时间单位、错误分类和实验元数据约定，分别实现／验证，不强求共享同一段代码，也不让运动控制依赖会自动恢复且丢失诊断字段的标准状态转换。

## 4. 公共能力抽取建议

建议先在 `aimdk_test` 内整理 `common/` 子包，现有 CLI 入口不变。只有第二个业务包实际需要这些能力时，再提升为独立 `aimdk_common` 包，避免先创建通用框架。

| 能力 | 源码证据 | 建议抽取范围 | 必须保留的业务差异 |
| --- | --- | --- | --- |
| 实验 JSONL 日志 | [head_test_diagnostics.py](../src/test/aimdk_test/head_test_diagnostics.py) 已同时被头部和手臂使用 | 移至 `common/diagnostics.py`；统一事件基本字段、实验标识及输出目录参数 | JSONL 是实验事件日志，MCAP 是消息记录；不合并写入机制。现有缓冲截断计数、退出写盘行为需要保留 |
| 反馈时效与时钟检查 | [head_test_core.py](../src/test/aimdk_test/head_test_core.py) 的 `FeedbackMonitor` 被 [arm_test_core.py](../src/test/aimdk_test/arm_test_core.py) 的 `Stream` 使用，并通过字符串替换消除 `head` | 提取无 ROS 导入的命名流监视器；显式配置流名和接收／源时间阈值，保留错误锁存策略 | 头部、手臂、MC 的当前阈值和必需数据不同；控制校验失败应中止，采集器仍应保留原始异常证据，不能复用为录包过滤器 |
| 五次平滑插值 | 两个 core 文件重复 `t ** 3 * (10 - 15 * t + 6 * t * t)` | 提取纯数学 `quintic_blend`，保留各自的路径检查与目标数组构造 | 头部双槽位与双臂 14 关节、往返与单段的语义不同，不统一为隐含关节顺序 |
| 端点驻留判定 | `EndpointMonitor` 与 `ArmEndpoint` 都维护连续达标时间和超时 | 在已有行为覆盖后，提取参数明确的纯逻辑判定器 | 当前头部 0.5°、手腕 0.2°、其他臂关节 0.3°等阈值不同；不能抽取时顺便放宽 |
| 有界服务请求 | `head_test.py`、`arm_test.py`、`arm_test_motion.py`、`volume_control.py` 都处理超时和结果 | 如后续抽取，仅共享截止时间、future 清理和由调用方提供的等待回调 | 手臂等待时仍须执行反馈／控制权检查及可能的末帧保持；音量可使用普通等待。服务返回结构也不同，不能直接用音量客户端替换运动请求逻辑 |
| 模式切换与退出 | 头部 `Port` 与手臂 `ArmExecution` 均有模式查询、轮询、交接 | 本轮保留在各自业务适配器；只记录共同协议与差异 | HEAD_ONLY 与 URS 的控制权、夹爪、末帧保持及退出门槛不同，暂不合并状态机 |

当前 `head_test_core.py` 和 `arm_test_core.py` 未导入 ROS；这是应保留的算法／适配分离。`ArmExecution` 属于 ROS 执行适配层，不应放入纯算法公共模块。`arm_test_core.py` 同时放置反馈解码与运动实验规则，可按职责分成模块，但不必为此新建多个 ROS 包。

日志定位还有目录耦合：[DiagnosticLog](../src/test/aimdk_test/head_test_diagnostics.py) 通过 `src/test/package.xml` 探测工作区。建议让显式 `--log-dir` 成为实验启动配置，默认目录只作后备；目录调整时保留兼容入口并检查从安装空间启动的行为。

## 5. 采集与观测之间的数据边界

[采集节点](../src/data_collection_edge_agent/src/data_collection_edge_agent_node.cpp) 当前只订阅 `sensor_msgs/msg/JointState` 和 `sensor_msgs/msg/Imu`。参数只能改变话题名，不能改变消息类型；直接把话题改为厂商双臂反馈，不会自动支持 `aimdk_msgs` 类型。

标准状态适合通用曲线和后续分析，但转换后的消息不足以保留所有域错误、关节错误、夹爪状态、模式及厂商扩展时间字段。下一阶段应同时规划原始厂商话题与标准状态，选择可配置的序列化录制或显式类型支持；本轮不决定实现路线，不把现有两话题采集器记作完整上肢记录链路。

观测包负责解释厂商状态、保留源时间、发布标准状态；当前无效原因只写日志，结构化有效性诊断待补充；采集器负责保存配置的话题和自身录制状态，不因实验判定失败丢弃原始证据。后续用独立实验标识关联 JSONL、MCAP 和 SDK／固件／参数信息，不让采集器触发实验运动。

固定 best-effort、depth=10 和回调中持锁写盘是当前实现。先在容器测量数据率、写盘延迟和丢帧，再决定是否增加按话题 QoS 配置及有界写入队列；不能从 README 的“高频”描述推定已达到目标吞吐。
