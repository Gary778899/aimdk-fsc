# X2 Ultra 遥操开发规划

更新：2026-10-29。状态：已完成上游文档及部分源码审阅，尚未复现或真机验证。

## 目标与路线

先复现 [Agibot-X2-IK-upper-body-control](https://github.com/AgiBot-Community/Agibot-X2-IK-upper-body-control)，确认其模型、IK 与 URS 执行链路适配当前 X2 Ultra，再扩展双臂同步笛卡尔控制，最后接入 PICO。

基线：上游提交 `4445980`、模块 `x2ik 2.1.0`。机器人侧源码位于 wheel/runtime 内；`source/` 主要包含桌面与标定工具。复现时保留版本及修改差异，不将上游声明记为本机验收结果。

首期范围为固定站姿下双臂末端与夹爪遥操，保留原厂下半身运控。头部、行走、视频回传后置，不引入全身策略或 HAL 接管。

```text
上游单臂 MoveJ / 笛卡尔运动复现
  → 本机模型、TCP、反馈和补偿适配确认
  → 单一执行器同步推进左右末端轨迹
  → PICO 相对位姿映射与连续目标更新
  → 双臂、夹爪联动和数据采集
```

## 阶段一：复现并确认适配

| 工作 | 实现方法 | 完成依据 |
| --- | --- | --- |
| 模型与接口核对 | 对照实际机型核查 URDF、左右关节名称/轴向/零位/限位、消息槽位、URS 与 RUNNING、IMU 坐标 | 形成模型与接口对应表，解决发现的不一致 |
| 只读 FK/IK | 用实测关节角计算 FK，再对该位姿做 IK→FK；分别检查左右臂及不同姿态 | 记录模型内残差、解支、求解耗时；不把数学残差当实际定位精度 |
| TCP 核对 | 先用腕原点，再核查 `gripper` 名义中心；必要时填写自定义工具外参 | 明确实际工具点；独立测量平移和方向，不能只改 TCP 名称 |
| 单臂运动复现 | 左右分别执行小范围 MoveJ，再执行平移、旋转和完整位姿目标；另一侧保持 | 记录目标、发送值、实测关节及反馈 FK，核对方向、连续性和实际运动 |
| 补偿评估 | 保留上游固定补偿作为复现条件，记录原 IK 目标、位置偏置与最终下发值；必要时在明确修改的版本中对照 | 确认当前姿态与负载下的效果、限幅情况；不推定为通用补偿 |

**运动前先处理已知契约差异：**上游夹爪模式发送 `[0, 0]`，不能解释为保持；应按本项目契约保持采样开度。模式查询需核对 URS **及 RUNNING**；沿用本项目反馈源时间推进、接收时效与错误锁存检查，补齐补偿所用 IMU 的时效检查。所有适配单独记录，区分原版观察与适配版结果。

上游固定补偿为 `Δq = clip(τg / 40, ±12°)`，随后再次裁剪关节限位；这会改变 IK 原目标。复现中须观察偏置与限位裁剪，不直接移植为本项目默认行为。终端普通 `q` 会双臂 HOME，`q!` 才直接退出；本项目运动入口仍不自动返程或切换模式。

阶段完成条件：左右臂在明确的姿态范围、工具和负载下通过验证，形成适配结论与未覆盖范围；不以少数点位宣称全工作空间完全适配。

## 阶段二：双臂同步笛卡尔控制

上游 MDI 一次只接收 `left` 或 `right` 的笛卡尔目标；公开 `Robot.moveJ(q_left, q_right)` 仅提供双臂关节同步。需要新增双臂笛卡尔执行器。

1. 同时采样左右关节起点，计算两侧 TCP 初始位姿。
2. 使用共同时间进度 `a(s)=10s³−15s⁴+6s⁵`，分别生成位置线段和旋转插值：
   `p=p0+a(p1−p0)`，`R=R0·Exp(a·Log(R0ᵀR1))`。
3. 每周期分别调用两侧 `SrsArmIK.track()`，维护独立的关节种子、SEW 臂角和解支。
4. 两侧候选均通过检查后，按名称映射为完整 14 关节目标，由一个发布器下发；单侧失败不让另一侧继续推进该同步轨迹。
5. 保留失败原因和最后已接受目标；异常处理沿用本项目契约，不自动重试、HOME 或切换模式。

先验证无硬件目标回放，再由用户验证双臂小范围同步运动。记录周期耗时、两侧末端残差、解支变化与原始反馈；50 Hz 只作为上游初始节奏，是否满足持续执行需实测。该执行器不自带碰撞规划，首轮仅覆盖已检查的动作空间。

## 阶段三：PICO 接入

复用 [Unity-Client](https://github.com/XR-Robotics/XRoboToolkit-Unity-Client)、[PC-Service](https://github.com/XR-Robotics/XRoboToolkit-PC-Service) 和 [PC-Service-Pybind](https://github.com/XR-Robotics/XRoboToolkit-PC-Service-Pybind)，无需先修改头显客户端。

```text
PICO → PC Service → XR 输入适配
     → 相对位姿映射 → 双臂连续 IK → AimDK 上肢发布
```

- 输入适配：读取左右 controller 位姿、Grip、Trigger、跟踪有效性和源时间；保留序号与接收时间。若输入进程放在 PC，通过明确的数据协议送入机器人容器，不依赖本地 Kilted 控制机器人。
- 位姿映射：Grip 按下时记录手柄与机器人 TCP 参考。将手柄位置增量经坐标变换和尺度映射叠加到 TCP 参考；姿态增量经一致的坐标变换后合成。统一为 `torso_link`，核对四元数顺序、单位、轴向和左右手系。
- 连续求解：不逐帧调用阻塞式 MoveJ/MDI；新增周期循环，消费最新目标并调用 `track()`。位置与姿态平滑、速度约束依据接口和实测确定，不任意堆叠阈值。
- 接管语义：Grip 松开时停止更新该侧目标；重新按下重新建立参考。跟踪丢失、断链、头显重定位后不自动续接旧目标。保持与退出行为需在阶段一核实；停止发布不是急停。
- 夹爪：Trigger 映射到开度目标，按现有完整消息契约发送；验证实际开度关系，不宣称力保持。先空爪验证，再增加物体操作。

完成依据：先单臂、后双臂验证跟随、松手、重新接管及断链处理；保存 XR 输入、末端目标、IK 结果、实际下发值、原始反馈与模式记录。反馈采集复用现有采集器，缺失的 XR/目标记录另行补充，不改变采集器只读边界。

## 关键算法与代码入口

下表为上游 wheel 中 `x2ik/` 内的函数；内部接口不等于上游承诺的公开 API。

| 文件 / 函数 | 用途与复用方式 |
| --- | --- |
| `x2_arm_model.py`：`ArmModel.forward_kinematics()` | 关节到 TCP 位姿；模型核查与反馈误差计算基础 |
| `x2_srs_ik.py`：`solve()`、`solve_at_psi()` | 搜索 SEW 臂角与解析分支，生成终点逆解 |
| 同上：`polish()` | 按完整模型进行阻尼数值精修 |
| 同上：`sew_angle()`、`track()` | 冗余臂角计算及连续解支跟踪；双臂/PICO 的核心复用对象 |
| `x2_mdi.py`：`_solve_pose()`、`Session.plan_pose()` | MDI 目标预检参考 |
| `x2_sim_ros.py`：`goto_cartesian()` | 单臂位姿插值与逐帧 IK；扩展双臂执行器的参考 |
| `x2_api.py`：`X2Arm.ik()`、`move_l()` | 内部单臂算法/运动封装，非顶层公开接口 |
| `x2_movej.py`：`Robot.moveJ()` | 已公开的单臂/双臂关节运动，用于阶段一复现 |
| `x2_sim_ros.py`：`_send_upper()` | 最终消息与位置偏置；重点核查，不原样替换现有发送层 |
| `source/tools/calibrate_tcp.py` | 离线 TCP 平移拟合，不负责运动采样或方向标定 |

## 实现归属与验证约定

- 上游复现基线独立保存，不直接覆盖现有功能。复用源码前核实项目自身许可；第三方模型许可不能自动代替项目代码许可。
- 后续输入、映射、IK 适配和 ROS 执行分模块放入 `aimdk_functions`；算法部分不导入 ROS，现有 `dual_arm_control` 单次命令契约不变。新增入口注册与依赖按包约定维护。
- Codex 默认只进行本地文档、语法及静态检查；机器人依赖的构建、运行与验证由用户同步后在 Humble 容器完成。本规划不展开部署命令。
- 阶段交付依次为：**适配验证记录 → 双臂笛卡尔执行器 → PICO 遥操闭环**。每阶段结论注明版本、环境和验证范围。
