# X2 Ultra 官方 v1.3.0 与上肢 IK 参考项目模型比对

日期：2026-10-29。方式：本地文件静态比对；按用户要求由 subagent 执行并整理。当前机器人型号与模型版本按根目录 AGENTS.md 确认为 X2 Ultra / v1.3.0。

## 结论

**两套 URDF 的几何与惯性数据一致，关节位置限位不完全一致。** 两边均有 41 个 link、40 个 joint（31 个 revolute、9 个 fixed）；12 个关节的上下限存在差异，其中双臂占 6 个：左右肩 roll、左右腕 pitch、左右腕 roll。全部 31 个转动关节的 `effort`、`velocity` 相同。

对于双臂，上游肩 roll 比官方 v1.3.0 更窄，腕 pitch 和腕 roll 的部分边界则更宽。不能把参考项目的限位整体视为更保守或直接用于本机。模型几何相同为提取 FK/IK 提供了依据；IK 的可行解集合及最终裁剪仍必须适配。

附带 MJCF 也不完全相同：除同样的 12 处位置范围差异外，参考项目缺少 pelvis 的显式惯性，并有 13 个 motor 的 `ctrlrange` 不同。尤其参考代码关于“官方 v1.3.0 MJCF 腕部为 ±2.2”的注释，与本次用户提供的官方文件不符。

## URDF 几何、惯性与资源检查

完整文本差异仅为上述 12 行 `<limit lower=... upper=...>` 以及文件结尾换行差异；未发现其他文本内容变化。XML 属性复核结果：

| 检查项 | 结果 |
| --- | --- |
| robot 名称、link/joint 名称及数量 | 相同 |
| 全部 joint 的 type、parent、child | 相同 |
| 全部 joint 的 origin xyz/rpy 与 axis xyz | 相同，包括肩、肘、腕与固定传感器变换 |
| 全部 link 的 inertial origin、mass、完整 inertia 张量 | 相同 |
| visual/collision 的 origin、geometry、material 及 mesh 文件路径/scale | 相同 |
| 关节 effort、velocity | 全部相同 |
| 关节位置 lower/upper | 12 个关节不同，见前两表 |
| 9 个 fixed joint | 相同；无位置 limit 可比较 |

本次两份 URDF 没有仅由资源路径替换造成的差异。只比较了 XML 中的网格引用，没有对官方网格顶点进行逐个比较；wheel 也未附带完整 mesh 目录，因此不能将“引用相同”表述为网格实体已经验证一致。

## 附带 MJCF 的额外差异

两份 MJCF 均有 32 个 body、31 个常规 joint、31 个 motor，compiler 角度单位均为 radian。每份 MJCF 的 31 个 joint range 与其各自 URDF 的位置范围一致，因此官方与参考之间仍有同样的 12 个关节位置范围差异。

除这些 range 外，按具名路径比较 XML 属性得到：

| 项目 | 官方本次 v1.3.0 资源 | 参考 wheel 资源 | 影响范围 |
| --- | --- | --- | --- |
| `pelvis/inertial` | 存在：`pos="-0.001209 -2.3e-05 -0.002011"`，`mass="3.523487"`，`diaginertia="0.0126 0.007924 0.012417"` | 无此元素 | 不可认定全身仿真惯性等价；不是双臂URDF FK差异 |
| 左右 hip pitch/roll/yaw、左右 knee、waist yaw motor `ctrlrange`（共9个） | `[-120, 120]` | `[-118, 118]` | MJCF actuator 控制范围不同 |
| 左右 wrist pitch/roll motor `ctrlrange`（共4个） | `[-4.8, 4.8]` | `[-2.2, 2.2]` | 参考 `tau_max_safe` 会采用较小值 |

其余可配对元素的属性相同，包括 body 变换、joint 轴向/位置、其余惯性、mesh 引用、默认参数、传感器与 motor 属性；两边 `joint actuatorfrcrange` 保持一致，腕 pitch/roll 均为 `[-4.8, 4.8]`。因此参考文件内部同时存在 wrist `actuatorfrcrange=±4.8` 与 motor `ctrlrange=±2.2`，不能混为同一字段。

参考 `x2_arm_model.py:231` 的 `parse_mjcf_ctrlrange()` 以及 `x2_arm_dynamics.py:186` 的 `feedforward_torque()` 注释提及“官方 v1.3.0 的 URDF 为4.8、MJCF为2.2”。**该注释与本次官方文件不相符；本次文件两者均为4.8。** 不据此判断其他发行包或历史文件的情况，也不据此推断驱动保护的实际阈值。

## 参考代码如何消费这些参数

以下行号均对应固定版本 wheel 内 `x2ik/` 源码。

| 位置 | 实际行为及适配含义 |
| --- | --- |
| `x2_arm_model.py:32`、`:258` | 默认读取同包 `x2_ultra.urdf` 与 `x2_ultra.xml`，并按左右关节名称建立模型；默认不会使用本项目 `underlay/extra/` 资源 |
| `x2_arm_model.py:278` | URDF lower/upper 直接形成 `q_min/q_max`；effort、velocity 分别进入 `tau_max/dq_max` |
| `x2_arm_model.py:283` | 解析 MJCF motor ctrlrange，与URDF effort取较小值得到 `tau_max_safe`；这不修改位置限位 |
| `x2_arm_model.py:563`、`:566` | `clamp()` 直接裁剪至模型范围；`within_limits()` 使用模型范围及调用方容差 |
| `x2_srs_ik.py:265` | 肘角上下限参与可达范围估计；此次两份肘限位相同 |
| `x2_srs_ik.py:439` 及批量后端 | 解析候选及批量筛选依赖模型限位；不能只在发布端改一份范围 |
| `x2_srs_ik.py:941` | 数值求解对种子与更新步骤调用 `clamp()` |
| `x2_api.py:291` | 关节目标先检查是否在模型限位内，不接受越界终点 |
| `x2_sim_ros.py:427` | 上肢发送前先裁剪两臂位置，再加位置偏置，再裁剪一次；其结果可能不等于原IK目标，并会处理未选手臂 |
| `x2_compensation.py:8` | 公开入口固定参数为 stiffness=40、bias_limit_deg=12、gravity_source=pelvis；这些参数并非官方URDF中的标定量 |
| `x2_arm_dynamics.py:166` | 位置偏置由重力模型与设定刚度计算，并按偏置上限裁剪；该函数不使用 `tau_max_safe` 作为位置偏置限幅 |

因此替换 URDF 会同时改变候选可行性与最终位置裁剪；替换 MJCF 则改变 `tau_max_safe`，不能把两种变化作为一个不加说明的“模型升级”。当前原生上肢路径发送位置目标，不应引入参考代码的其他 HAL/力矩发送路径。

## 对遥操提取适配的建议

1. 以本次官方 v1.3.0 URDF 作为机器人模型来源，固定文件哈希；参考项目模型单独保留为复现基线。记录改动前后结果，不能将新结果记为原版复现。
2. 几何相同，可以继续提取 `ArmModel`、`SrsArmIK` 与 `x2_srs_batch`；明确注入官方模型路径或包内受版本管理的模型资源，避免算法隐式读取wheel旧模型。
3. 区分模型范围和已核实的执行范围。首版遥操沿用本项目已约定范围，并与官方模型求交核查；在建立IK求解器及批量缓存前注入同一份执行范围，供求解与最终目标检查共同使用。本轮不扩大现有肩roll或腕部动作范围。
4. 对原IK目标、位置偏置、最终发送值分别记录；拒绝不可接受的目标，不靠末端静默裁剪掩盖不一致。未选关节保持采样值的既有契约单独保留。
5. wrist motor 的2.2/4.8来源差异单独记录，后续按实际接口语义核实。它不构成采用力矩控制、修改现有增益或认定固件额定能力的依据。
6. 后续用户在Humble容器先做只读反馈FK→IK→FK及限位附近目标检查，再做左右臂小范围运动。数学残差、候选连续性、实际TCP精度和补偿效果分别评价。
