## 目标与阶段边界

第一阶段建立“实际关节反馈 → FK/IK → 单臂目标 → 原生上肢执行 → 反馈与日志”的最小闭环，确认模型、限位、TCP 和执行契约适配当前 X2 Ultra，为后续双臂同步笛卡尔控制与 PICO 连续遥操提供基础。

保留原厂下半身运控，使用 URS 原生上肢接口。左右臂分别验证，未选手臂和夹爪保持本次采样目标。运动入口默认只读，显式 `--execute` 才创建命令发布器；不自动 HOME、返程或切换模式。停止发布不能解释为硬件急停或固件必然持续保持。

本阶段不接入 PICO、不开发视频回传、头部或行走控制，不增加 HAL 接管、全身策略或碰撞规划。无硬件回放可用于验证目标生成，不能替代实体运动与定位验证。

## 步骤 1：固定来源并确定提取范围

1. 保存参考提交、wheel/runtime 哈希、所选文件清单及许可说明；原始资源与适配差异分别留档。项目自有代码许可在复制合入前核实，模型许可不能代替代码许可。
2. 成组提取以下数学模块，保留原始算法结构，先通过薄适配层接入本项目：

| 模块 | 用途与处理 |
| --- | --- |
| `x2_arm_model.py` | FK、雅可比与模型几何；显式注入本机模型路径和工具变换 |
| `x2_srs_ik.py`、`x2_srs_batch.py` | 初始求解、数值精修、SEW 臂角与连续解支跟踪；两者存在直接依赖，必须一起提取 |
| `x2_tcp.py`、`assets/tcp_presets.json` | TCP 配置及腕到工具的完整变换 |
| 官方 v1.3.0 URDF | 本机模型资源；保留来源和哈希，安装后不依赖开发者本地绝对路径 |
| `source/tools/calibrate_tcp.py` | 需要工具标定时再适配；仅拟合 TCP 平移，方向独立测量 |
| `x2_frames.py`、`x2_arm_dynamics.py`、`x2_compensation.py` | 单独整理为补偿评估所需依赖，不作为首版默认发送行为 |

3. `goto_cartesian()`、MDI 预检和 MoveJ 仅作为流程参考；不将整个 `x2_sim_ros.py`、SSH 桥接或桌面 AppImage 作为业务依赖。公开 `Robot.moveJ()` 是阻塞关节运动接口，不是连续遥操接口。

完成依据：形成来源与改动清单，数学模块无 ROS 导入，模型加载位置明确，许可待确认项有记录。

## 步骤 2：建立包内适配与统一参数

实现归属为 `src/functions/aimdk_functions/`，不新建公共包，不依赖官方示例或 `aimdk_test`。建议按职责组织，文件名在实施时确定：

| 模块职责 | 实施内容 |
| --- | --- |
| `upper_body_kinematics/` | 模型、IK、批量后端、TCP 与薄适配层 |
| `upper_body_cartesian_core.py` | 无 ROS 的位姿插值、连续求解及候选检查 |
| `upper_body_ros.py` | 原始反馈、模式确认、完整上肢消息发布 |
| `upper_body_diagnostics.py` | 求解、目标、偏置、发布、反馈与阶段记录 |
| 验证命令入口 | 默认只读，显式执行；命令实现后再提供准确用法 |

优先复用 `dual_arm_control_core.py` 中的关节名称、解码、源时间监视及错误锁存。ROS 适配参考现有 `DualArmPort`，不直接套用单次动作状态机；确有复用需要时才提取最小订阅与发布能力，保持原命令契约。

参数适配要求：

- 形成左右 14 关节名称、模型索引、SDK 消息槽位对应表。反馈按名称读取，发送按接口规定顺序组装。
- 区分官方模型范围与本项目执行范围。按2026-10-29用户要求，新遥操路径以固定参考项目URDF的14关节限位为基准，左肩roll下限降低1°、右肩roll上限提高1°，其余边界采用原始参考值，不再与官方模型或既有命令范围取交集；官方URDF几何保持原样。在建立求解器及批量缓存前注入一致范围，最终发布前再次检查，参数报告记录参考提交/哈希、原始范围及边界调整。
- 参考限位按名称保存在包内`reference_joint_limits.json`，肩roll调整单独保存在`parameters.py`，不改写原始参考数据；完整数值见功能包说明。腕roll采用参考左下限-1.571/右上限1.571rad，腕pitch采用±0.558rad，不顺带修改旧命令。调整后的肩roll左下限/右上限为约∓0.07845329252rad，最新SD右肩反馈已在该边界内，完整求解结果待用户重验。
- 未选关节保持采样值，不因替换模型而被自动裁剪；若影响所选动作的必要条件不满足，明确报告并拒绝该动作。
- 统一 `torso_link`、m、rad；核对姿态矩阵方向及四元数顺序，左右分别建模，不能整组取负代替另一侧。
- 按 Humble/Python 3.10 环境维护依赖、模型安装资源和 console_scripts；新增或修改脚本的全部函数提供中文用途说明的 docstring。

完成依据：模型/接口对应表可审阅，算法与发送端限位一致，包依赖与安装资源完整。

## 步骤 3：只读反馈与 FK→IK→FK

由用户同步后在机器人 Humble/AimDK 容器验证。只读入口不创建运动发布器、不调用模式切换；记录实际模式，不将只读数学检查结果当作运动授权。

步骤三已实现入口 `ros2 run aimdk_functions upper_body_kinematics_check`，
准确的构建、采样、合成失败用例及日志回传流程见[功能包说明](../overlay/src/functions/README.md#步骤三实际反馈的只读-fkikfk-验证)。
先持续接收并保存快照，再关闭订阅进行求解；计算阶段不宣称实时反馈。
用户已回传单个SD实际姿态的双侧往返结果；多个姿态与扩大覆盖后续按实验需要进行。

1. 接收完整双臂反馈，记录原始名称、位置、速度、effort、错误、源时间、接收时间及序号。保留源时间推进、时效与错误锁存检查。
2. 左右分别以腕原点 TCP 计算实测关节角的 FK，输出 `torso_link` 下的位置和姿态。
3. 以 FK 位姿为 IK 目标、当前关节角为种子，执行 IK→FK，记录位置/旋转残差、种子距离、SEW 臂角、解析分支及耗时。
4. 在多个实际可采样姿态重复；记录左右差异、无解及超限原因。冗余手臂存在多解，不要求逆解关节角必然逐项等于输入。
5. 在无发布模式下检查限位附近、超出执行范围和不可达目标，确认不会把目标静默裁剪后报告为原目标成功。

完成依据：两侧均有可复核的输入、模型、目标和结果记录，模型内一致性与失败行为明确。几何相同或数学残差小不能证明实际零位、轴向和 TCP 定位精度，后续运动仍需确认。

## 步骤 4：连续求解与无硬件轨迹回放

在容器中以已保存的起点和小范围目标生成轨迹，仅写入结果，不创建命令发布器。

1. 以共同五次进度形式生成单臂位置线段及旋转插值：
   `a(s)=10s³−15s⁴+6s⁵`，`p=p0+a(p1−p0)`，`R=R0·Exp(a·Log(R0ᵀR1))`。
2. 初始求解与周期跟踪分开；逐帧调用 `track()`，维护上一条已接受关节目标、SEW 臂角及分支。
3. 首版显式设置 `clamp_reach=False`、`fallback=False`，避免默认工作空间投影改变目标，或周期内全局搜索造成耗时突增。无解返回明确失败，不自动重试或放宽姿态。
4. 独立检查候选有限性、限位、FK残差、关节步长和分支变化。阈值沿用有明确依据的约定；尚无依据的时序、稳定性和精度指标先记录分布，不任意设为阻断门槛。
5. 记录每周期耗时及其分布、最大关节步长、残差和失败帧。50 Hz 为初始目标节奏，上游性能注释不能代替机器人容器测量。

完成依据：平移、旋转及组合目标均有完整回放；失败时最后已接受目标可追溯，未隐藏投影、姿态降级或裁剪。双臂统一提交在后续阶段实现，本阶段保留独立求解状态接口。

## 步骤 5：核对 TCP

1. 先固定腕原点 `none`，确认工具切换前后的关节与模型约定。
2. 再核对 `gripper` 名义中心。平移在各侧腕坐标表达，必须同时应用旋转；不能将局部平移直接加到 torso 位置。
3. 对实际夹爪工具点进行独立测量，分别记录平移和方向。必要时使用 custom 工具外参，并保留工具版本。
4. 需要枢轴拟合时，先明确人工采样流程，再复用离线标定脚本；它不负责自动运动采样，也不能从平移拟合推出方向标定结果。

完成依据：日志明确报告采用腕原点、名义夹爪中心或已标定工具点；外部测量结果与模型 FK 分开保存。

## 步骤 6：适配执行层并验证单臂运动

当前先提供最小入口`upper_body_move`：一次快照→单轴平移端点的局部IK→
MoveJ式关节五次插值，默认只读、显式`--execute`发送。零位移保留当前关节角，
非零目标关闭投影/全局兜底，单关节总变化沿用10°实验上限。
该入口仅验证一次关节路径到达笛卡尔端点，不保证TCP中间路径为直线，
不代表步骤四完整轨迹回放或本节全部动作已实现；准确用法见功能包说明。

运动前由操作者进入 URS，程序有界查询实际目标模式及 `RUNNING`，运行期间继续监视模式、反馈和错误。使用 `/mc/upper_body_command`，始终发送左7＋右7完整 rad 目标、模式1和左右夹爪开度；未选手臂和夹爪固定重发本次采样目标。

依次完成下列小范围运动，每项先只读查看计划，再由用户显式执行：

| 顺序 | 动作 | 核对内容 |
| --- | --- | --- |
| 1 | 左右分别进行小范围关节插值运动 | 关节槽位、正负方向、目标和实际增量；另一侧保持；不使用 HOME 作为默认首个目标 |
| 2 | 单臂平移，保持参考姿态 | torso 轴向、反馈 FK 与实际运动方向、轨迹连续性 |
| 3 | 单臂旋转，保持 TCP 位置 | 固定轴/工具轴乘法约定、工具外参影响 |
| 4 | 单臂完整位姿目标 | 连续解支、执行范围、发送周期及反馈跟踪 |
| 5 | 正常结束及中断退出观察 | 是否停止发布、退出后的真实保持/超时表现；不自动返程或切换模式 |

幅度和时长在对应命令实现时结合现有约定与现场动作空间明确，不沿用上游 HOME 或未经核实的工作空间。模型附近的越界/断流等情况优先通过回放和消息注入验证，不为验证故障主动制造实体危险。

沿用本项目已有源时间、接收时效、跟踪误差及异常中止契约；新执行器是否直接复用单次命令的终点规则，在实现中单独说明。停止发布不表示完成物理恢复。

完成依据：左右分别有明确姿态、工具和负载下的运动记录，包含请求、计划、发送值、实际关节、夹爪、模式及反馈 FK；实际TCP误差以独立测量为依据。

## 步骤 7：单独评估位置偏置补偿

上游参数为 `Δq=clip(τg/40, ±12°)`，之后再次裁剪位置限位。该算法改变IK目标，不自动成为本项目默认行为。

本轮实现：`upper_body_line`和`upper_body_move`增加`--compensation`，默认仍关闭。
采用包内官方v1.3.0模型惯性，标为适配版；骨盆IMU四元数加具名三腰反馈换算重力，
沿用既有源时间推进、年龄、接收时效及错误锁存，不使用旧缓存或静态重力兜底。
固定刚度40及±12°偏置限幅不变；为从采样目标平滑接入，偏置乘以本次运动的
五次进度，终点使用完整偏置。最终关节目标越限拒绝，不进行上游的二次位置裁剪。
未选臂与夹爪保持采样值；既有±3°跟踪/到位条件与退出行为不变。
原IK路径10°变化约束仍针对IK目标；额外偏置单独记录，最终发送值检查执行限位。
先只读逐点预览，再由用户在声明姿态、工具和负载下显式执行，准确命令见
[功能包说明](../overlay/src/functions/README.md#步骤七显式位置偏置补偿)。已有实机对比观测见
[上肢验证汇总](x2_upper_body_validation_20261029.md)，不据此认定通用补偿收益。

1. 保留上游固定参数实现和资源作为复现条件，同时记录为满足本项目夹爪、反馈、模式与退出契约所作的修改，结果标为适配版。
2. 先离线计算偏置；使用本机模型的版本与参考原模型版本分别标记，不能混入同一次原版结论。
3. 真机对照先由用户确认姿态、工具、负载和补偿配置；记录原IK目标、重力估计、原始偏置、限幅情况及最终发送值。
4. 补齐所用 IMU 和腰反馈的源时间、接收时效及坐标检查；无有效重力输入时不能以旧缓存宣称补偿有效。
5. 评估未选手臂保持行为，不能对保持目标擅自加偏置。对不符合执行范围的最终候选明确报告，不靠静默裁剪掩盖差异。
6. 用明确修改的配置开展有/无补偿对照，分别评价反馈跟踪、实际末端偏差和偏置限幅；不推定为通用重力力矩补偿。

完成依据：能解释每个发送目标相对原IK目标的变化，并形成限定工况下的对照结论或暂不启用的依据。
