# X2 Ultra 遥操第一阶段：上肢适配与验证

更新日期：2026-10-30。适用 X2 Ultra、SDK 1.1、机器人 Humble 容器与官方 URDF v1.3.0。
本文定义第一阶段的实现契约、验证顺序和完成条件；总路线见[遥操开发规划](dev_teleop.md)，当前命令与参数见[功能包说明](../overlay/src/functions/README.md)。开发、同步和验证分工遵循 [AGENTS.md](../AGENTS.md)。

## 目标与当前状态

建立“实际关节反馈 → FK/IK → 单臂目标 → 原生上肢执行 → 反馈与日志”闭环，为双臂同步笛卡尔控制与 PICO 连续遥操提供基础。首阶段验证模型、限位、TCP 和单臂执行，PICO、视频回传、头部及行走控制留在后续阶段。

依据用户回传日志，来源适配、只读求解、连续局部 IK、完整路径发送、规划后反馈刷新和记录闭环已跑通。当前证据包括单个 SD 调整姿态的双侧 FK→IK→FK、小幅端点与直线运动，以及左臂 10mm、20mm 有／无位置偏置补偿记录。覆盖范围和日志索引见[上肢验证汇总](archive/x2_upper_body_validation_20261029.md)。

实体直线精度、姿态保持、TCP 标定及未覆盖动作仍待验证。补偿实验的反馈 FK 终点误差改善，但起点不同且样本有限，现有结果不足以调整补偿参数或既有 ±3° 到位条件。本次仅整理文档，未重新执行机器人验证。

## 统一适配契约

### 来源、模型与包归属

参考项目为 `/home/gary/projects/Agibot-X2-IK-upper-body-control`，提交 `444598038cf0e5b27e32e3e5295ab24503ecd43f`，版本 `x2ik 2.1.0`。算法来自 wheel 的 `x2ik/`，对应模型与 runtime 逐字节一致。来源、哈希及差异依据见[模型比对记录](archive/x2_urdf_v1_3_comparison.md)。

实现位于 `overlay/src/functions/aimdk_functions/`，数学模块保持无 ROS 导入，模型作为包资源安装。职责划分如下：

| 模块 | 职责 |
| --- | --- |
| `upper_body_kinematics/` | 模型、FK、雅可比、IK、批量后端、TCP 与薄适配层 |
| `upper_body_cartesian_core.py` | 位姿插值、连续求解、候选检查 |
| `upper_body_ros.py` | 原始反馈、模式确认、完整上肢消息发布 |
| `upper_body_diagnostics.py` | 求解、目标、偏置、发送、反馈与阶段记录 |

`x2_srs_ik.py` 与 `x2_srs_batch.py` 成组维护；TCP 使用完整腕到工具变换。`x2_frames.py`、动力学与补偿模块用于独立补偿评估。枢轴标定工具仅拟合 TCP 平移，方向另行测量。上游桌面程序、SSH 桥接和整个 `x2_sim_ros.py` 不作为业务依赖。

### 坐标、限位与反馈

- 坐标统一为 `torso_link`、m、rad，明确旋转矩阵方向及四元数顺序。左右臂分别建模，维护 14 关节名称、模型索引与 SDK 槽位对应关系；反馈按名称读取，发送按接口顺序组装。
- 几何与惯性采用官方 v1.3.0 完整模型。遥操执行范围采用固定参考 URDF 的 14 关节限位，左肩 roll 下限降低 1°、右肩 roll 上限提高 1°，其余采用参考原值。求解器、批量缓存与发送检查使用一致范围。
- 原始参考范围保存在 `upper_body_kinematics/assets/reference_joint_limits.json`，肩 roll 调整保存在 `parameters.py`。完整数值统一见功能包说明；参数报告保留参考提交／哈希、原始范围及调整量。统一入口的joint、tcp与补偿后目标共用这份范围。
- 保留源时间推进、接收时效、错误锁存与异常中止。未选关节保持采样值；候选超限明确失败，目标不静默裁剪。

官方与参考 URDF 有 12 个关节位置范围不同，其中双臂涉及 6 个关节；MJCF 另有惯性与 motor 范围差异。逐项数值与哈希统一由模型比对记录维护，模型字段的适用范围须与原生执行接口分别核对。

### 执行行为

运动入口默认只读，显式 `--execute` 创建发布器。操作者预先进入 URS，程序有界查询实际目标模式及 `RUNNING`，执行中持续监视模式、反馈与错误。

使用 `/mc/upper_body_command`，发送左 7＋右 7 的完整 rad 目标、模式 1 与左右夹爪开度。未选手臂及夹爪固定重发本次采样目标。保留原厂下半身运控，不自动 HOME、返程或切换模式；退出停止发布，实体保持和超时表现通过现场观察记录。

## 验证步骤与完成条件

### 1. 来源与包适配

当前已完成算法与模型的包内适配，模型作为包资源加载，求解与发送端使用一致的执行范围，依赖和入口面向 Humble／Python 3.10。

### 2. 只读 FK→IK→FK

入口为 `ros2 run aimdk_functions upper_body_kinematics_check`。先接收并保存实际反馈快照，再关闭订阅求解；记录模式，不创建运动发布器或切换模式。

左右分别以腕原点 TCP 计算 FK，再以该位姿为 IK 目标、实际关节角为种子回算 FK。记录输入、位置／旋转残差、种子距离、SEW 臂角、分支和耗时。逐步扩展实际姿态，并在无发布模式检查边界、超限及不可达目标；多解允许与种子不同。

完成条件：两侧输入、模型、目标及结果可复核，失败原因明确。已有单快照结果；实体零位、轴向和 TCP 精度由后续独立测量确认。

### 3. 连续求解与无硬件回放

以保存的起点生成平移、旋转和组合轨迹，仅写结果。共同五次进度为 `a(s)=10s³−15s⁴+6s⁵`，位置为 `p=p0+a(p1−p0)`，姿态为 `R=R0·Exp(a·Log(R0ᵀR1))`。

初始求解与逐帧 `track()` 分开，维护上一条已接受目标、SEW 与分支。显式设置 `clamp_reach=False`、`fallback=False`；无解明确失败，不自动重试或放宽姿态。检查候选有限性、限位、FK 残差、关节步长与分支变化，沿用已有明确依据的门槛，其余指标先记录分布。

完成条件：三类轨迹均有完整记录，失败帧和最后已接受目标可追溯；报告周期耗时分布、最大步长、残差及失败情况。50 Hz 为初始目标节奏，后续双臂负载依据容器实测评估。

### 4. 单臂运动

当前入口为 `upper_body_control joint/tcp/gripper`，支持单侧或双侧。TCP默认直线，端点模式通过 `--path endpoint` 显式选择；两种路径及参数统一见[功能包说明](../overlay/src/functions/README.md)。旧入口已移除，历史命令见[归档](archive/upper_body_commands_before_unification_20261030.md)。

统一调度已实现同一次采样、双侧独立预规划、共同时间轴和完整消息发布，双臂实机验证待完成。单臂既有验证结果不扩展为统一入口验收。

原 IK 路径的单关节总变化沿用 10° 实验上限，具体参数与到位条件见功能包说明。各动作先只读审阅，再由用户显式执行：

| 动作 | 核对内容 |
| --- | --- |
| 左右分别小范围关节运动 | 槽位、方向、目标／实际增量、另一侧保持 |
| 单臂平移并保持姿态 | torso 轴向、反馈 FK、实体方向及连续性 |
| 单臂旋转并保持 TCP 位置 | 旋转乘法约定与工具外参 |
| 单臂完整位姿 | 连续解支、执行范围、发送周期与反馈跟踪 |
| 正常结束与中断 | 停发、实体保持及超时表现 |

完成条件：左右臂在声明姿态、工具和负载下分别有请求、计划、发送、关节反馈、夹爪、模式及反馈 FK 记录；实体 TCP 误差以独立测量评价。已有小幅执行结果，旋转、完整位姿和退出表现按实际覆盖补齐。边界和断流优先通过回放／消息注入检查。

### 5. 位置偏置补偿对照

`upper_body_control joint/tcp` 默认开启补偿，`--no-compensation`用于关闭对照；纯gripper不接受补偿参数。当前适配版采用官方 v1.3.0 惯性，以骨盆 IMU 四元数和具名三腰反馈换算重力，保留时间、时效与错误检查；无有效输入时拒绝使用旧缓存或静态重力兜底。

偏置为 `Δq=clip(τg/40, ±12°)`，乘本次运动的五次进度从零接入，终点使用完整偏置，仅作用于所选臂。最终目标越限拒绝，未选臂及夹爪保持采样值。原 IK 路径的 10° 约束与额外偏置分别记录，既有 ±3° 跟踪／到位条件及退出行为保持现有契约。

先逐点只读预览，再在明确姿态、工具与负载下执行对照。记录原 IK 目标、重力估计、原始偏置、限幅及最终发送值，区分官方模型适配版与参考原版。后续对照采用相同起点、明确负载和重复实验，分别评价反馈跟踪、反馈 FK 与实体末端偏差。

完成条件：每个发送目标的变化可解释，形成限定工况下的启用或暂不启用依据。已有有限样本结果见验证汇总，通用收益待验证。

### 6. TCP 核对

当前暂按法兰面中心等同腕原点 `none`；待办为独立验证法兰中心位置与方向，再核对 `gripper` 名义中心。工具平移在各侧腕坐标表达，转换到 torso 时同时应用腕旋转。

独立测量实际工具点的平移和方向；采用 custom 外参时记录工具版本。枢轴拟合使用人工采样及离线处理，方向标定单独完成。

完成条件：日志明确采用腕原点、名义中心或标定工具点，模型 FK 与外部测量分别保存。当前实体测量待完成。

## 记录与阶段交付

每次验证保存代码／模型版本、环境、SDK／固件（未知项明确标记）、有效限位、TCP、负载、配置及结果。事件覆盖原始反馈与时间、请求位姿、候选、SEW／分支、残差、偏置、发送值、周期耗时、模式及退出原因。

原始反馈与命令录制复用独立采集器，求解和阶段记录由验证模块补充。当前 `upper_body_control` 使用 `UpperBodyLog` 逐事件写入并 flush。日志获取沿用现有任务，分析输出放 `exports/`。

双臂实机验证需核对：

- 两侧模型、限位、名称／槽位及 TCP 明确，已发现差异有处理结果或适用限制。
- 左右单臂完成声明范围内的关节与笛卡尔验证，失败和退出行为有记录。
- 补偿配置及适用工况明确，原 IK、偏置与发送值可区分。
- 实测周期数据足以评估后续双臂负载。

单次双臂命令已采用共同时间进度、两侧独立预规划与单发布器，尚待容器构建及实机验收。后续连续遥操采用两侧独立 IK 状态。两侧候选均通过后统一提交种子、SEW、分支及完整目标；任一侧失败，两侧均不推进该周期。先回放、再真机，随后接入 PICO 相对位姿映射与接管语义；连续遥操使用周期目标接口。

## 待确认事项

- **实体测量：** TCP 平移／方向标定方式、直线与姿态保持的独立测量设备，决定步骤 4～6 的精度评价方法。
- **补充实验：** 左右臂姿态、工具、负载、幅度和重复次数，以及旋转／完整位姿入口的实施安排，决定未覆盖动作的验证范围。
- **补偿对照：** 相同起点与负载的实验配置、重复次数和评价指标，决定是否扩大补偿适用范围。
